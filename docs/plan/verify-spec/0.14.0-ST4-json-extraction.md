# VERIFY-SPEC — ST4 판정응답 JSON 추출 견고화

## 변경 파일
- `src/judge.ts` — `sliceBalancedObject`·`extractFirstJsonObject`(신규 private) · `parseVerdict` 배선
- `test/unit.test.mjs` — 신규 5건

## 구현 결정
- 탐욕적 `/\{[\s\S]*\}/` → **후보 `{`마다 균형 스캔 + 파싱 시도, 처음 성공하는 것 채택**.
  첫 `{`만 보지 않는 이유: 앞에 중괄호 낀 산문(`형식은 {verdict} 입니다`)이 올 수 있다.
- 문자열 리터럴·백슬래시 이스케이프를 인식 — reason에 `}`가 든 정상 응답을 깨뜨리지 않기 위해(회귀락 있음).
- 유효 객체 0개면 **기존과 동일하게 throw**(→fail-open). 절단 응답은 대상 아님(원인이 파서가 아니라 truncation).
- 배열·null 배제 형상가드 추가(review.ts readPendingReview와 같은 관례).
- **판정 프롬프트 무변경** → eval baseline 무변경이 정상 신호.

## 미확인 사항
- **실제 실패 원문을 못 봤다.** `failopen.log`는 에러 메시지만 남기고 raw 응답을 저장하지 않는다.
  재현은 동일 에러 클래스·동일 위치 패턴(`after JSON at position N (line M column 1)`)으로 일치시킨 것이고,
  daily-news-dispatch의 그 1건이 정확히 어느 형태였는지는 추정이다.
- 후보 순회는 `{` 개수만큼 파싱을 시도한다. 응답이 짧아 실질 문제는 없다고 판단했으나 상한을 두지 않았다.
- 이 수정은 **fail-open 전체를 없애지 못한다** — 이 저장소 fail-open 21건 중 이 유형은 3건이고,
  나머지(응답 절단·과거 버그)는 원인이 다르다. 절단 유형에 대한 처방(재시도·max_tokens)은 미착수.
